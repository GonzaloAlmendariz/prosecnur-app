## Initial Audit

## What Is Prehydrated

- BootGate: project/session status, warmup-plan, selected frontend module chunks,
  backend project/Monitoreo tasks.
- Territorial: active phase, light state, active scoped report, configured warmup
  scopes (`source`, `route_summary`, `advance_summary`,
  `validation_summary`, `queries_summary`) and map layers when field phase is
  relevant.
- Acreditacion: active view scope first, then `source`, `advance_summary` and
  `queries_summary` in the client warm cache.

## What Stays Lazy

- Territorial `full` report scope in normal navigation.
- Telefonico/accreditation `full` report unless the active view explicitly
  requires it.
- Mutating source sync/add/update actions.
- Final outputs, Sheets publish, PDF/download actions.
- Heavy map/inspector details outside the active territorial tab.

placeholder/error text such as `Preparando vista`, `Failed to fetch`,

## Visual Parity Is a Separate Gate

The hydration matrix only proves that a route, section or tab has loaded enough
visible data to stop blocking on placeholders/loaders. It does not prove that
the modular UI is visually or functionally equivalent to the canonical
`MonitoreoPage.tsx` original.

For that reason, visual parity is tracked with
`scripts/monitoreo-visual-parity-check.mjs`, which opens the canonical-vs-
modular comparator, waits until both frames are free of loading text, and saves
one PNG per declared section/tab in order. The first full Territorial run
against ACNURCG reached 24/24 ready but still showed large UI mismatches; those
mismatches remain product work, not measurement failures.
