## Current Apps Script Runner

The current Sheet has a legacy Apps Script runner named `SurveyMonkey` with
three menu actions:

- `Actualizar datos - flujo completo`: validates config, validates the official
  universe, syncs SurveyMonkey into the internal BBDD tabs, publishes the client
  report and validates outputs.
- `Actualizar solo AVANCE INTERNO`: syncs SurveyMonkey and rewrites the internal
  advance tabs, but does not publish the client report.
- `Actualizar solo REPORTE`: publishes the report from the existing internal
  BBDD without syncing SurveyMonkey.

Live `Estado ejecucion` evidence shows the full flow did run on
`28/06/2026 12:50:38` through `12:55:49` and processed the same raw Egresados
SurveyMonkey row counts as the Prosecnur sync:

- Egresados Web: 47 responses.

| Egresados | Correo | 26 | 0 | 26 |
| Egresados | Telefonico | 119 | 0 | 119 |

That explains the Sheet total of `145` completas and `0` parciales. The source
connection is not the problem; the discrepancy is in the Apps Script
classification/reconciliation logic versus the Prosecnur canonical case rollup.

Operational implication:

- The current Apps Script can publish an internal and external report, but it
  does not currently produce the same Egresados result as the updated `.pulso`.
- The Prosecnur Sheets publication endpoint produces the canonical result
  (`270 / 157 / 5 / 0 / 108`) for both client and internal audiences.
- If the existing Apps Script must remain the publisher, it needs to be patched
  to match the Prosecnur canonical classification and actor+case deduplication.
- The SurveyMonkey token is hardcoded in the Apps Script attachment; rotate it
  and move it to Apps Script properties before continuing operational use.
